## Prerequisites

- **Node 24+**, see `.nvmrc`.
- **Docker**, for ClickHouse and Redis.
- **[dbmate](https://github.com/amacneil/dbmate)**, a standalone binary rather than an npm package:

  ```bash
  brew install dbmate
  ```

## Setup

```bash
docker compose up -d     # ClickHouse and Redis
pnpm install
pnpm db:migrate          # creates the schema
pnpm dev                 # API on :3001, web on :3000
```

Then, in a second terminal:

```bash
pnpm cli health
```

Stop the containers with `docker compose down`, or `docker compose down -v` to drop the data as well.

## Scripts

| Command | Description |
|---------|-------------|
| `pnpm dev` | API and web app, both with hot reload |
| `pnpm typecheck` | Type-checks every package |
| `pnpm lint` | oxlint |
| `pnpm build` | Production bundle of the web app |
| `pnpm cli <args>` | Runs the CLI inside `demo/` |
| `pnpm db:migrate` | Applies pending migrations |
| `pnpm db:status` | Applied and pending migrations |

```
├── demo/           sample project; the CLI runs here
├── db/migrations/  dbmate migrations

```

## Notes

There is no build step. Node runs TypeScript directly, so relative imports carry
their extension: `import { api } from './index.ts'`.

Workspace packages export source. `@task/config` resolves to
`packages/config/src/index.ts`, and nothing needs building before anything else
runs.

`db/schema.sql` is generated by dbmate. Change the schema with a migration
(`dbmate new <name>`), not by editing the dump.

The API's routes are a single chained expression whose type is exported as
`ApiType`, which `hc<ApiType>()` turns into a typed client. See
`apps/cli/src/commands/health.ts`.
